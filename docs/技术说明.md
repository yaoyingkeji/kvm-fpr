# kvm-fpr 技术说明

本文档介绍 kvm-fpr 的架构设计、硬件指纹刷新原理、构建与打包方法。

---

## 1. 技术栈

| 组成 | 技术 | 许可 |
|---|---|---|
| GUI（版本一） | C + [NAppGUI](https://github.com/frang75/nappgui) | MIT（开源） |
| GUI（版本二） | C + GTK3 | LGPL（开源） |
| GUI（版本三） | C++ + Qt5 Widgets | LGPL（开源） |
| 后端（共用） | 系统调用 libvirt CLI（`virsh`）+ python3 | GPLv2（系统组件）/ PSF |
| 构建 | CMake / qmake + gcc | — |
| 打包 | dpkg-deb（.deb）、appimagetool（.AppImage） | — |
| **本项目源码** | C / C++ | **GPLv3（GPL-3.0-or-later）** |

**开源合规**：三个版本 GUI 库均为开源许可（NAppGUI MIT、GTK3/Qt5 LGPL，与 GPLv3
兼容），本工具源码以 **GPLv3** 协议发布，不依赖任何闭源库。

## 1.1 多版本实现

| 目录 | GUI 框架 | 语言 | 构建 |
|---|---|---|---|
| `src/` | NAppGUI（SDK） | C | `build.sh`（含 .deb / .AppImage 打包） |
| `gtk/` | GTK3 | C | `gtk/build_gtk.sh` |
| `qt/` | Qt5 Widgets | C++ | `qt/build_qt.sh` |

三个版本**共用同一套后端逻辑** `src/fpr.c` / `src/fpr.h`（列表、刷新指纹、sudo 封装、
指纹生成脚本），GUI 部分各自实现，界面功能完全一致：
虚拟机列表、sudo 密码、强制关机 / 重置 machine-id 选项、刷新按钮、
使用说明对话框、关于对话框（图标 + 版权 + 双邮箱 / 主页 / 项目主页可点击链接 + 协议）。

## 2. 代码结构

```
src/
├── main.c     # NAppGUI 图形界面（窗口、控件、事件回调）
├── fpr.c      # 后端逻辑（virsh 调用、sudo 封装、指纹生成）
└── fpr.h      # 后端接口定义
```

### 2.1 后端接口（fpr.h）

```c
typedef void (*FprLogFn)(void *ctx, const char *msg);

int fpr_list_vms(const char *sudo_pass, char ***names, int *count,
                 FprLogFn log, void *ctx);
/* 列出全部虚拟机 */

int fpr_refresh(const char *sudo_pass, const char *vm,
                int force_off, int reset_guest,
                FprLogFn log, void *ctx);
/* 刷新指定虚拟机的硬件指纹 */
```

### 2.2 关键实现细节

- **命令执行**：`popen` 捕获 stdout+stderr；需要 root 时通过
  `echo '<密码>' | sudo -S -p '' <命令>` 注入密码；
  所有命令前缀 `LC_ALL=C` 强制英文输出，避免因系统语言环境导致状态解析失败。
- **干扰过滤**：自动剔除 Deepin sudo 的"验证成功"提示行，保证导出的 XML 纯净。
- **状态轮询**：优雅关机后每秒轮询 `virsh domstate`，最长等待 90 秒。
- **开机自启保留**：`virsh dominfo` 检测 Autostart 状态，刷新后自动恢复。
- **nvram 处理**：检测到 `<nvram>` 时，`undefine --nvram --managed-save` 自动降级重试。

## 3. 硬件指纹刷新原理

刷新流程（`fpr_refresh`）：

```
1. virsh domstate <vm>           检查状态（若非关机，先关机）
2. virsh dumpxml <vm>            导出当前配置
3. 备份原始 XML → ~/kvm-fpr-backups/
4. python3 指纹生成脚本        生成全新指纹并写出新 XML
5. virsh undefine <vm>           移除旧定义（按需降级参数）
6. virsh define <新XML>          加载新定义
7. （可选）virt-customize        重置 guest 内部 machine-id
```

### 3.1 指纹生成规则（内嵌 python 脚本）

| 项 | 规则 |
|---|---|
| 域 UUID | `uuid.uuid4()`，替换 `<uuid>...</uuid>` |
| MAC 地址 | `52:54:xx:xx:xx:xx`（保留 KVM 厂商前缀），每张网卡独立随机 |
| SMBIOS serial | 24 位随机十六进制串，替换 `<serial>` 及 `entry name='serial'` |
| SMBIOS uuid | 重新生成 `system-uuid` / `product-uuid` / `uuid` 条目 |

仅当 XML 中存在 `<sysinfo type='smbios'>` 段时才重写 SMBIOS 条目，不影响其他部分。

### 3.2 guest 机器码重置

当勾选"重置 guest 内部 machine-id"且安装了 `virt-customize` 时：

```bash
virt-customize -a <磁盘> --run-command \
  'rm -f /etc/machine-id /var/lib/dbus/machine-id; systemd-machine-id-setup'
```

磁盘路径从 `virsh domblklist <vm>` 自动提取（跳过 cdrom 与空设备）。

## 4. 构建与打包

### 4.1 一键构建脚本

```bash
./build.sh                      # NAppGUI 版：二进制 + .deb + .AppImage
gtk/build_gtk.sh                # GTK3 版：编译 kvm-fpr-gtk
qt/build_qt.sh                  # Qt5 版：编译 kvm-fpr-qt
packaging/build_gtk_qt.sh       # 把 GTK/Qt 二进制打包为 .deb + .AppImage
```

脚本步骤（NAppGUI 版 `build.sh`）：

1. 克隆 NAppGUI 源码 SDK（`github.com/frang75/nappgui_src`，MIT）；
2. 将 `src/` 复制到 SDK 的 `src/kvmfpr/` 并注册目标；
3. `cmake -DNAPPGUI_DEMO=False -DNAPPGUI_WEB=False -DCMAKE_BUILD_TYPE=Release` 编译；
4. `dpkg-deb --build` 生成 .deb；
5. 下载 appimagetool，组装 AppDir，生成 .AppImage。

GTK3 版构建：`gcc main_gtk.c ../src/fpr.c $(pkg-config --cflags --libs gtk+-3.0)`（共用 `fpr.c` 后端）。
Qt5 版构建：`QT_SELECT=qt5 qmake main_qt.pro && QT_SELECT=qt5 make`（共用 `fpr.c` 后端）。

### 4.2 手动构建（分步）

```bash
# 1) 获取 NAppGUI SDK
git clone --depth 1 https://github.com/frang75/nappgui.git
# 系统依赖（Debian 系）
sudo apt-get install build-essential cmake libgtk-3-dev uuid-runtime

# 2) 把本项目 src/ 放入 SDK
cp -r src nappgui/src/kvmfpr
# 并在 nappgui/src/CMakeLists.txt 中注册：
#   desktopApp("kvmfpr" "kvmfpr" "osapp" NRC_NONE)

# 3) 编译（Release）
cmake -S nappgui/src -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_BUILD_CONFIG=Release
cmake --build build --target kvmfpr -j$(nproc)
# 产物：build/Release/bin/kvmfpr

# 4) .deb
dpkg-deb --build --root-owner-group packaging/ kvm-fpr_1.1.0_amd64.deb

# 5) .AppImage
appimagetool kvm-fpr.AppDir kvm-fpr-1.1.0-x86_64.AppImage
```

### 4.3 运行时依赖

- **必须**：`libgtk-3-0`、`libvirt-clients`（virsh）、`python3`、`sudo`
- **推荐**：`libguestfs-tools`（机器码重置功能）

> 程序本体为静态链接 NAppGUI 的单一可执行文件，不依赖 NAppGUI 运行时。

## 4.4 查看文件（XML 编辑查看）

- `fpr_dumpxml()`：导出虚拟机当前 XML（virsh dumpxml）
- `fpr_apply_xml()`：应用编辑后的 XML（先备份 → undefine → define，失败给出恢复路径）

## 5. 测试方法

```bash
# 1. 创建测试虚拟机
virsh define testvm.xml

# 2. 调用后端接口做端到端验证（绕过 GUI）
gcc -O2 -I src -o /tmp/fprtest src/fpr.c test/fpr_test.c && /tmp/fprtest

# 3. 对比刷新前后指纹
virsh dumpxml testvm | grep -E '<uuid>|<mac address'
```

`test/fpr_test.c` 为独立测试驱动，直接调用 `fpr_refresh()` 并打印日志，
可在无显示环境下验证完整刷新链路。
