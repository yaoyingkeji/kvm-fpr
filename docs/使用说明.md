# kvm-fpr 使用说明

本文档详细介绍 kvm-fpr（KVM 虚拟机硬件指纹刷新工具）的安装、操作与恢复方法。

---

## 1. 简介

kvm-fpr 用于刷新现有 KVM 虚拟机的硬件指纹与机器码：

- 生成**全新域 UUID**（对应 guest 看到的系统 UUID / DMI Product UUID）；
- 为每一张网卡生成**全新 MAC 地址**（保留 KVM 厂商前缀 `52:54:`）；
- 重写 **SMBIOS 序列号、系统 UUID 等条目**（如存在 `<sysinfo>` 段）；
- 可选：重置 guest 内部的 **machine-id（机器码）**。

刷新后，虚拟机对操作系统、应用软件、授权系统而言，表现为一台全新的机器。

---

## 2. 系统要求

| 依赖 | 说明 |
|---|---|
| 操作系统 | Deepin / Debian / Ubuntu 等 Linux 发行版 |
| libvirt | `libvirt-clients`（提供 `virsh`），已安装 libvirt 的宿主机自带 |
| sudo | 程序需要 root 权限执行 `virsh define`（写入 `/etc/libvirt/qemu/`） |
| GTK3 | `libgtk-3-0`（GUI 运行库） |
| python3 | 用于执行内嵌的 XML 指纹生成脚本 |
| virt-customize（可选） | `libguestfs-tools`，勾选"重置 guest machine-id"时需要 |

---

## 3. 安装

提供三种 GUI 实现（功能一致，见 Release 页面）：

| 版本 | 安装包（.deb） | AppImage |
|---|---|---|
| NAppGUI 版 | `kvm-fpr_1.0.0_amd64.deb` | `kvm-fpr-1.0.0-x86_64.AppImage` |
| GTK3 版 | `kvm-fpr-gtk_1.0.0_amd64.deb` | `kvm-fpr-gtk-1.0.0-x86_64.AppImage` |
| Qt5 版 | `kvm-fpr-qt_1.0.0_amd64.deb` | `kvm-fpr-qt-1.0.0-x86_64.AppImage` |

### 3.1 通过 .deb 安装（Deepin / Debian / Ubuntu）

```bash
sudo dpkg -i kvm-fpr_1.0.0_amd64.deb       # NAppGUI 版
sudo dpkg -i kvm-fpr-gtk_1.0.0_amd64.deb   # GTK3 版
sudo dpkg -i kvm-fpr-qt_1.0.0_amd64.deb    # Qt5 版
```

安装后：

- 可执行文件：`/usr/bin/kvm-fpr`、`/usr/bin/kvm-fpr-gtk`、`/usr/bin/kvm-fpr-qt`
- 桌面入口：应用菜单中搜索"KVM 指纹刷新工具"

卸载：

```bash
sudo dpkg -r kvm-fpr kvm-fpr-gtk kvm-fpr-qt
```

### 3.2 通过 .AppImage 运行（任意发行版，免安装）

```bash
chmod +x kvm-fpr-1.0.0-x86_64.AppImage
./kvm-fpr-1.0.0-x86_64.AppImage
```

## 4. 操作步骤

### 4.1 刷新虚拟机指纹

1. 启动程序；
2. 点击 **「刷新列表」**，下拉框中出现本机所有虚拟机（含已关闭的）；
3. 选择目标虚拟机；
4. 输入 **sudo 密码**（root 用户可留空）；
5. 按需勾选：
   - **「运行中则强制关机」**：虚拟机正在运行时直接 `destroy`（不保存 guest 内数据）；
     不勾选则先优雅关机，等待最长 90 秒；
   - **「重置 guest 内部 machine-id」**：同时重置 guest 的 `/etc/machine-id`
     与 `/var/lib/dbus/machine-id`（需安装 `virt-customize`，耗时数分钟）；
6. 点击 **「刷新硬件指纹 / 机器码」**；
7. 日志区输出完整过程：新旧 UUID、新旧 MAC、备份路径等。

### 4.2 日志解读

```
>> 虚拟机 myvm 当前状态：shut off        ← 虚拟机必须处于关机状态
>> 已导出当前配置：/tmp/kvmfpr_..._orig.xml
>> 原始配置已备份：~/kvm-fpr-backups/myvm_时间戳_orig.xml
   旧 MAC：52:54:00:aa:bb:cc              ← 刷新前的指纹
   新 MAC：52:54:0d:84:a6:8b              ← 刷新后的指纹
   新 UUID：52dcfe68-31e6-4cc8-a780-5ff526913712
>> 已移除旧定义（方式 1）
>> 新配置已生效！
[完成] 虚拟机 myvm 硬件指纹已刷新
```

### 4.3 恢复备份

每次刷新前，原始 XML 会自动备份到：

```
~/kvm-fpr-backups/<虚拟机名>_<时间戳>_orig.xml
```

如需恢复原指纹：

```bash
sudo virsh define ~/kvm-fpr-backups/<虚拟机名>_<时间戳>_orig.xml
```

> 注意：恢复的是刷新前的域定义（旧 UUID / 旧 MAC），虚拟机的磁盘数据不受影响。

## 5. 常见问题

### Q1：提示"无法获取虚拟机列表"？
- 确认 sudo 密码正确；
- 确认宿主机已安装并启动 libvirtd（`systemctl status libvirtd`）；
- 确认当前用户在 `libvirt` 用户组（`sudo usermod -aG libvirt $USER`）。

### Q2：提示"等待关机超时"？
- guest 系统关机缓慢或拒绝关机，勾选「运行中则强制关机」重试。

### Q3：提示"未安装 virt-customize"？
- 勾选了机器码重置但未安装工具。安装后重试：

  ```bash
  sudo apt-get install libguestfs-tools
  ```

### Q4：刷新后虚拟机无法启动？
- 立即用备份恢复：

  ```bash
  sudo virsh define ~/kvm-fpr-backups/<虚拟机名>_<时间戳>_orig.xml
  ```

### Q5：会动到虚拟机磁盘数据吗？
- 不会。工具只修改 libvirt 域定义（XML）与 guest 的 machine-id 文件，
  不修改磁盘分区与业务数据。

---

## 6. 注意事项

- 刷新会短暂**关闭虚拟机**，请提前保存 guest 内的工作；
- Windows guest 在刷新后可能提示"硬件变更"，属于预期行为（全新指纹的效果）；
- 含 UEFI 安全启动的虚拟机在刷新时会重建 nvram，密钥库随之重置；
- 本工具为系统级操作工具，请仅在你拥有权限的虚拟机与宿主机上使用。
